# Сборка портативного Open Antigravity (без ключа, с вашим прокси внутри)

Эта инструкция — для самостоятельной сборки на Windows из изменённых исходников.
Что изменено по сравнению с оригиналом:

| Что | Как |
|---|---|
| **Без ключа** | Лицензионная система полностью удалена — GUI и TUI сразу открываются на главном экране |
| **Прокси вшит в билд** | Адрес задаётся при сборке переменной `AG_BUILTIN_PROXY` и работает по умолчанию, пока вы не вписали в поле «Свой прокси» что-то своё. Пароль хранится в exe в XOR-обфусцированном виде (от `strings`-дампа; от целенаправленного реверса не спасёт) |
| **Портативность** | Все данные — в папке `data\` рядом с exe. Никаких задач в планировщике, копии в `ProgramData`, записей в реестре. Релей запускается из той же папки, его пид лежит в `data\relay.pid` |
| **Встроенные автообновления** | Проверка релизов GitHub в 1 клик с фоновой загрузкой, распаковкой и бесшовным перезапуском |

---

## 1. Что понадобится

- Windows 10/11 x64, ~3 ГБ свободного места, интернет.
- **Rustup** — установщик: <https://rustup.ru> (или <https://win.rustup.rs/x86_64>). При установке выбирайте дефолт (**stable-msvc**).
- Важно: **rustc ≥ 1.95** — eframe 0.36.1 (зафиксирован в `Cargo.lock`) требует именно такую версию. Если rustup ставился давно: `rustup update stable`, затем `rustc --version` должен показать 1.95 или новее. Даунгрейд egui/eframe через `cargo update --precise` не делайте — исходники написаны под API 0.36 и со старыми версиями не соберутся.
- **Visual Studio Build Tools 2022** — <https://visualstudio.microsoft.com/downloads/> → «Build Tools для Visual Studio», в установщике отметить workload **«Разработка классических приложений на C++»** (нужен линкер MSVC).
- Время: первая сборка 10–20 минут (большие зависимости: eframe/wgpu), дальше — минуты.

Проверка, что тулчейн жив, — в новом окне терминала:

```bat
cargo --version
```

## 2. Впишите свой прокси

Задайте прокси параметром `--proxy` или через переменную окружения:

```bat
build.cmd --proxy "aguser:ПАРОЛЬ@IP_ВАШЕГО_VPS:48123"
```
или:
```bat
set "AG_BUILTIN_PROXY=aguser:ПАРОЛЬ@IP_ВАШЕГО_VPS:48123"
build.cmd
```

Формат строго такой: `логин:пароль@хост:порт` — обычный HTTP-прокси с CONNECT
(ваш tinyproxy на Dokploy именно такой). Пароль может содержать `@` и `:`,
разделитель — **последний** `@` перед хостом.

Опечатку сборка сама не пропустит: `build.rs` проверяет формат и пишет
предупреждение `cargo:warning=...`, если строка не похожа на
`логин:пароль@хост:порт`.

## 3. Соберите

Запустите `build.cmd` (двойной клик или из терминала из корня папки с исходниками). Скрипт:

1. вызывает `cargo build --release` с нужными переменными;
2. складывает результат в `dist_portable\`:

```
dist_portable\
├── OpenAntigravity.exe          — сама программа (иконка и портативный режим уже вшиты)
└── README.txt                   — короткая памятка
```

Если собираете вручную, без скрипта:

```bat
set "AG_BUILTIN_PROXY=aguser:ПАРОЛЬ@IP:48123"
set "AG_PORTABLE=1"
cargo build --release
```

При сборке с `AG_PORTABLE=1` портативный режим уже скомпилирован в бинарник.

## 4. На флешку и запуск

1. Скопируйте **всю** папку `dist_portable` на флешку.
2. Запустите `OpenAntigravity.exe`. Когда включите переключатель DNS, выскочит UAC —
   это нормально: установка NRPT-правил требует прав администратора.
3. Работает сразу: вшитый прокси включён по умолчанию, поле «Свой прокси»
   уже показывает его.

**Как это устроено внутри:**

- все настройки/логи — в `data\` рядом с exe; удалить `data\` = полный сброс;
- релей (`--dns-forwarder`) запускается из той же папки, без планировщика;
  его пид — в `data\relay.pid`;
- на ПК ничего не остаётся: ни задач, ни `ProgramData`, ни автозапуска;
- после перезагрузки просто запустите exe ещё раз — автозапуск это
  единственное, чего портативный режим сознательно не делает (автозапуск =
  установка);
- «Выключить всё» в программе стирает `data\` — как и оригинал стирает свою
  папку состояния.

## 5. Что в этой сборке работает

Работает всё, что построено на **DNS-маршруте** и на **«Своём прокси»** —
для вашей схемы (tinyproxy на VPS в Германии) этого достаточно:

- патч клиента / автораспатч;
- DNS-слой (NRPT + локальный релей на `127.0.0.53:53`);
- локальный CONNECT-прокси и маршрут Own через ваш tinyproxy.

**Не работает** (и не соберётся): приватные маршруты автора — встроенные
выходы (exits) и релей (relay). Их файлы `src/relay.rs`, `src/exits.rs` и
`.relay_key`/`.exits` в открытом репозитории отсутствуют; `build.rs` честно
печатает `private routes: relay=false exits=false`. Вам они не нужны: ваш
прокси и есть выход.

## 6. Если что-то не так

| Симптом | Причина / что делать |
|---|---|
| `error: rustc X is not supported by the following packages: ecolor/eframe/egui ... requires rustc 1.95` | Устаревший тулчейн: `rustup update stable`, проверьте `rustc --version` (нужно ≥ 1.95) и собирайте заново. Внутри WSL2/Docker свежий rustup — там ошибки не будет |
| `cargo not found` | Терминал открыт до установки rustup — откройте новый; или PATH не дописан |
| `error: linker 'link.exe' not found` | Не установлены VS Build Tools с C++ workload (п.1) |
| `cargo:warning=AG_BUILTIN_PROXY не похож на ...` | Опечатка в строке прокси; формат `логин:пароль@хост:порт` |
| «релей не запустился» | Смотрите `data\forwarder.log`: чаще всего порт 127.0.0.53:53 держит старый процесс — перезагрузитесь или `taskkill /F /IM OpenAntigravity.exe` |
| Прокси сменился на VPS | Впишите новый в поле «Свой прокси» (записанный в поле адрес старше вшитого) и пересоберите, если нужно навсегда |
| Антивирус ругается на exe | Обычное дело для сборок с NW.js-патчами/прокси; добавьте в исключения или проверьте сборку сами |

## 8. Сборка под Linux (в т.ч. SteamOS / Steam Deck)

В репозитории уже есть Linux-порт (см. `linux/README.md`): окно на OpenGL,
терминальный режим TUI (сам включается без графического сеанса, например по
SSH), патч клиентских бинарников и JS, локальный прокси как systemd **user**
юнит + `AG_LS_PROXY` через `~/.config/environment.d`. Всё под обычным
пользователем, sudo не спрашивается.

На Linux **не работает** DNS-слой (NRPT-правила и релей `:53`) — это
Windows-механизм, там он заглушен. Для схемы с вашим tinyproxy это не
ограничение: локальный прокси Linux-порта использует вшитый адрес как
апстрим напрямую, ошибка 400 «region» уходит через ваш VPS.

Все правки этой сборки действуют и на Linux: без ключа, прокси вшит,
данные в `data/` рядом с бинарником (`portable.flag` рядом с exe включает
портативный режим так же, как на Windows).

### 8.1 Способ 1 — Docker на вашем VPS (проще всего: Docker уже стоит ради Dokploy)

В пустую папку на VPS положите исходники (git clone или `scp -r` папки
`repo-antigravity` с Windows-машины), затем:

```bash
cd ~/src   # папка с исходниками, рядом build_portable.sh
docker run --rm -v "$PWD":/src -w /src \
  -e AG_BUILTIN_PROXY='aguser:ПАРОЛЬ@IP_ВАШЕГО_VPS:48123' \
  rust:1-bookworm bash build_portable.sh
```

**Для GUI-окна на Deck добавьте `-e AG_MUSL=0`** — получите обычную
glibc-сборку (2.36), которая открывает окно на SteamOS; без этого флага
будет musl-статика, живущая только в терминале (п. 8.3). Универсальный
вариант с окном и проверкой обновлений:

```bash
docker run --rm -v "$PWD":/src -w /src \
  -e AG_MUSL=0 \
  -e AG_BUILTIN_PROXY='aguser:ПАРОЛЬ@IP_ВАШЕГО_VPS:48123' \
  -e AG_UPDATE_URL='https://ваш-сайт/version.json' \
  rust:1-bookworm bash build_portable.sh
```

Скрипт сам поставит нужные apt-пакеты внутри контейнера и соберёт релиз;
результат появится на хосте в `./dist_portable_linux/`. Кэш сборки между
запусками экономит именованный volume: добавьте `-v agcargo:/usr/local/cargo`.

Забрать на свою машину / на Deck:

```bash
scp -r user@vps:~/src/dist_portable_linux .
```

Проверка архитектуры: `uname -m` должно быть `x86_64`.

### 8.2 Способ 2 — WSL2 на вашей Windows-машине (сборка Linux-бинарника, не выходя из Windows)

```powershell
wsl --install -d Ubuntu-22.04
```

(при необходимости перезагрузка, при первом старте Ubuntu — логин/пароль).
Дальше в терминале Ubuntu:

```bash
# 1. Rustup: внутри WSL ставится свежий stable сразу (eframe 0.36.1 требует rustc >= 1.95)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source ~/.cargo/env

# 2. Исходники — ВНУТРЬ файловой системы WSL, не собирайте на /mnt/c (медленнее в 5-10 раз)
cp -r /mnt/c/Users/ВАШ_ЛОГИН/Downloads/repo-antigravity ~/src
cd ~/src

# 3. Сборка (apt-пакеты скрипт поставит сам через sudo)
AG_BUILTIN_PROXY='aguser:ПАРОЛЬ@IP_ВАШЕГО_VPS:48123' bash build_portable.sh

# 4. Забрать результат на Windows
cp -r ~/src/dist_portable_linux /mnt/c/Users/ВАШ_ЛОГИН/Desktop/
```

Дальше папка `dist_portable_linux` — на флешку/SD и на Deck (п. 8.4).

Три важных замечания:
- exe, собранный на Windows, на Linux не работает — Linux-версия собирается
  в WSL2 или Docker (получается ELF x86-64).
- `build_portable.sh` по умолчанию собирает **универсальный glibc-бинарник**
  на базовой версии glibc 2.36 (Debian 12 Bookworm) — он совместим со всеми
  современными дистрибутивами (SteamOS на Deck, Ubuntu 22.04+, Fedora, Arch),
  поддерживает графическое окно (Wayland/X11) на дисплее Steam Deck (1280x800)
  и автоматически переключается в терминальный режим (TUI) на серверах без дисплея.
- DNS-слой на Linux теперь полностью поддержан: адреса unblock-резолверов
  закрепляются в `/etc/hosts` (через графический запрос пароля Polkit/pkexec при
  необходимости) с автоматическим сбросом кэша systemd-resolved.
- Для полностью статической сборки без glibc (TUI-only) передайте `AG_MUSL=1`.

### 8.3 Что получается

```
dist_portable_linux/
├── open_antigravity — универсальный ELF x86-64 (полноценный GUI + TUI)
├── launch.sh        — умный запуск: разрулит noexec-носитель и графику/TUI
├── icon.png         — иконка для ярлыков
└── README.txt       — краткая памятка
```

Универсальный бинарник:
- **На Steam Deck и обычных ПК с графикой**: открывает аккуратное графическое
  окно (размер 560x720 адаптирован под экран Steam Deck 1280x800 с панелью задач).
- **На сервере / SSH / без графического сеанса**: автоматически переходит в TUI
  (терминальный интерфейс на клавишах).
- **DNS-обход**: работает через избирательный пиннинг в `/etc/hosts` — с нулевой
  задержкой, без конфликта с VPN или systemd-resolved. При нехватке прав
  вызывает стандартное графическое окно пароля Polkit (KDE/GNOME) без необходимости
  запуска всей программы от root.

### 8.4 SteamOS (Steam Deck) — запуск

1. **Desktop Mode**: кнопка питания → «Переключиться на рабочий стол».
2. Скопируйте папку `dist_portable_linux` на Deck — USB-флешка, SD-карта,
   `scp` (в SteamOS включён sshd не по умолчанию; проще всего флешка или
   Syncthing/KDE Connect).
3. Откройте **Konsole** (в Desktop Mode), перейдите в папку и выполните
   `bash launch.sh`. Без sudo — и не нужно. Носитель, смонтированный с
   `noexec` (NTFS/FAT32-флешка), не проблема: launch.sh сам перенесёт
   бинарник в `~/.local/share/openantigravity` и запустит оттуда.
4. Установите Linux-версию Antigravity **в домашнюю папку** — `/opt` на
   SteamOS read-only, snap не патчится. Приложение находит установку в
   `~/.local/share/antigravity` само; нашёл не всё — карандаш «✏» в строке.
5. В окне приложения — «Включить всё», затем **полностью перезапустите
   Antigravity** (языковой сервер подхватит `AG_LS_PROXY`).
6. Опционально: `bash install.sh` — ярлык «Open Antigravity» в меню
   приложений.

На SteamOS приложение в системные каталоги не пишет: только домашняя папка
(`~/.config/environment.d`, `systemctl --user`, файлы Antigravity) и папка
`data/` рядом с бинарником. Root FS остаётся нетронутым, обновления SteamOS
ничего не затирают.

В Game Mode приложение не запускается — там только игры; всё делается в
Desktop Mode.

### 8.5 Если что-то не так (Linux)

| Симптом | Причина / что делать |
|---|---|
| `error: failed to run custom build command` (pkg-config) | Не стоят dev-пакеты: `sudo apt install pkg-config libxkbcommon-dev libwayland-dev` (в Docker-способе скрипт ставит сам) |
| «нет доступа к графическому дисплею» / окно не открывается на Deck | У musl-сборки GUI нет по построению (п. 8.3): работайте в TUI из Konsole (`bash launch.sh`) или пересоберите с glibc в Docker (`AG_MUSL=0`, п. 8.1). Также бывает при запуске через sudo — запускайте без него |
| Окно не открывается по двойному клику | Нет графического сеанса или права на исполнение: запустите `bash launch.sh` из Konsole — он скажет причину или откроет TUI |
| `bash: ./open_antigravity: Permission denied` | Так и задумано: запускайте через `bash launch.sh`, он сам выставит права (или `chmod +x open_antigravity`) |
| Antigravity не найден | Указан путь вручную (карандаш «✏»); установка в `/opt` или snap — перенесите в `~/.local/share` |
| Ошибка 400 осталась | Проверьте, что Antigravity перезапущен **после** включения тумблера; `systemctl --user status open-antigravity-proxy` должен быть active |
| Свой прокси сменился | Впишите новый в поле «Свой прокси» (записанный адрес старше вшитого) и пересоберите, если нужно навсегда |

## 9. Проверка обновлений (ваш собственный version.json)

В сборку встроен механизм «новая версия»: приложение само (раз в 8 часов и по
кнопке) скачивает маленький JSON с вашего сайта и, если там версия новее
её собственной, показывает жёлтый баннер со ссылкой на скачивание.

### 9.1 Как это работает

- **Адрес фида** вшивается при сборке переменной `AG_UPDATE_URL` (как и
  прокси). Пока она не задана — проверка полностью выключена: ни запросов,
  ни баннера, кнопка в TUI честно скажет «URL не задан».
- В рантайме адрес можно переопределить той же переменной:
  `AG_UPDATE_URL='https://зеркало/version.json' ./open_antigravity` — например,
  чтобы переключить зеркало или отключить проверку (`AG_UPDATE_URL= `).
- Поддерживаются http и https (VPS с Dokploy без сертификата — не проблема),
  редиректы 301–308 следуются.
- Результат кэшируется в temp на 8 часов; кнопка «Проверить обновления»
  всегда проверяет по-настоящему.
- Ссылка в баннере: `url_windows` на Windows, `url_linux` на Linux/SteamOS,
  иначе `page`.

### 9.2 Формат version.json

```json
{
  "version": "1.1.3",
  "notes": "кратко: что нового",
  "page": "https://ваш-сайт/",
  "url_windows": "https://ваш-сайт/OpenAntigravity_windows_v1.1.3.zip",
  "url_linux": "https://ваш-сайт/OpenAntigravity_linux_v1.1.3.tar.gz"
}
```

Обязательно только `version`; остальные поля необязательны.

### 9.3 Как выпускать новую версию

1. Измените версию в файле `VERSION` (например `1.1.3`).
2. Запустите сборку: `build.cmd --package` (Windows) или `bash build.sh --package` (Linux).
3. При релизе через GitHub: создайте тег `git tag v1.1.3 && git push origin v1.1.3`.
   GitHub Actions автоматически всё соберёт и опубликует.

У пользователей старой сборки появится баннер со ссылкой на обновление.

### 9.4 Где кнопки

- **GUI**: футер → «Проверить обновления» (результат — рядом, исчезает через
  15 с; при найденной версии поднимается баннер сверху).
- **TUI**: клавиша `u` (результат — строка-тост; найденная версия — в
  заголовке окна).

## 10. Диагностика и ярлыки

В сборку добавлены встроенные кроссплатформенные инструменты (Linux + Windows):

### 10.1 Самодиагностика сети и системы (`src/platform/diag.rs`)
Комплексный self-test: окружение, локальный прокси, DNS-слой, TCP/HTTP CONNECT/TLS к апстриму и Unblock DNS:
- **CLI**: `open_antigravity --check` (или `open_antigravity --diagnose`) с цветным ANSI-выводом.
- **GUI**: кнопка **«🩺 Проверить всё»** в блоке «Диагностика окружения (Doctor)» и «Тест сети» (результаты проверки пишутся в журнал).
- **TUI**: горячая клавиша **`d`** (запуск теста без зависания интерфейса, подробности в журнале).
- Результаты диагностики автоматически включаются в сохраняемый файл отчёта.

### 10.2 Ярлыки рабочего стола и меню (`src/platform/shortcut.rs`)
- **CLI**: `open_antigravity --shortcut` (Рабочий стол и меню приложений).
- **GUI**: кнопка **«Создать ярлык на Рабочем столе»** в блоке «Система и запуск».
- **TUI**: горячая клавиша **`s`**.

## 11. Упаковка релиза

Скрипты `build.sh` (Linux) и `build.cmd` (Windows)
автоматизируют полный цикл выпуска новой версии.

### 11.1 Что делают

1. Собирают релизный бинарник и формируют портативный дистрибутив.
2. Упаковывают `dist_portable_linux/` в `OpenAntigravity_linux_v{VER}.tar.gz`
   (или `dist_portable\` в `.zip` на Windows) с версионным именем папки
   внутри архива.
3. Считают SHA256 и кладут рядом (`.sha256`).
4. При `--site URL` генерируют `version.json` для фида обновлений.

### 11.2 Использование (Linux)

```bash
# Автоматический релиз в 1 шаг (версия, тесты, коммит, git tag, git push)
bash build.sh --release 1.2.0

# Сборка + локальная упаковка (.tar.gz и AppImage)
bash build.sh --package

# Проверка и тесты
bash build.sh --check
```

### 11.3 Использование (Windows)

```cmd
rem Автоматический релиз в 1 шаг (версия, тесты, коммит, git tag, git push)
build.cmd --release 1.2.0

rem Сборка + локальная упаковка в ZIP
build.cmd --package

rem Проверка компиляции и прогон тестов
build.cmd --check
```

### 11.4 Результат

```
release/
├── OpenAntigravity_linux_v1.1.3.tar.gz       (или .zip на Windows)
├── OpenAntigravity_linux_v1.1.3.tar.gz.sha256
├── OpenAntigravity-x86_64.AppImage          (для Linux / Steam Deck)
└── version.json                             (информация о релизе)
```

### 11.5 Публикация

1. Загрузите архив и `version.json` на сайт.
2. URL в `version.json` должен совпадать с реальным расположением файлов.
3. Баннер «Новая версия» появится у пользователей в течение 8 ч (кэш).
4. Ручная проверка — кнопка «Проверить обновления» / клавиша `u` в TUI.
