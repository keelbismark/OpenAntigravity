# Postmortem: цепочка обхода региона Antigravity (v1.5.1 → v1.5.9)

**Период:** 2026-11-16 — 2026-11-17.
**Итог:** модель ответила на v1.5.9. Вход и запросы идут через FI-выход.
**Формат:** каждый слой описан от измеренного симптома. Ни одна гипотеза не
попала в код без воспроизведения — гипотезу про bound-сокет замер опроверг,
и правка была откачена.

## Как это выглядело снаружи

Одна и та же жалоба меняла текст по мере того, как устранялись слои:

1. `dial tcp 127.65.71.1:443: connect: connection refused`
2. `Post "…loadCodeAssist": Bad Gateway`
3. `read tcp …->127.65.71.1:443: wsarecv: An existing connection was forcibly closed`
4. `HTTP 400 … "User location is not supported for the API use."`

Каждый раз ошибка сдвигалась на один уровень вниз: клиент → дверь → локальный
прокси → выбор маршрута → выход в интернет. Ни один из этих слоёв не был виден
снаружи до тех пор, пока не был измерен.

| Слой | Симптом-доказательство | Настоящая причина | Версия |

## Ключевой приём, который сломал петлю

После четырёх попыток «исправить и выпустить» я добавил в отчёт **причину**
вместо очередной догадки:

```
Свой прокси: адрес не прочитан из C:\ProgramData\OpenAntigravity\data\upstream.txt
```

Одна эта строка показала и процесс (релей), и конкретный файл, и то, что окно
пишет в другое место. Следующая правка была точечной и сработала с первого раза.

## Уроки

1. **Два процесса — два источника правды.** Всё, что читают оба (настройки,
   upstream, состояние), должно публиковаться в одном месте и проверяться.
   Строка «Сборка службы: X (окно: Y)» теперь делает расхождение видимым.
2. **Состояние — в одном месте.** Два независимых таймера бана (`Health` и
   `routes`) расходились. Как только успешный проб стал снимать оба, маршрут
   вернулся.
3. **Избыточный флаг — будущая ложь.** `own_proxy_enabled` дублировал наличие
   адреса; выключение уже очищает адрес, значит флаг не нужен. Presence адреса
   и есть состояние.
4. **Диагностика раньше фикса.** Когда причина неизвестна, дешевле добавить
   одну строку в отчёт, чем выпускать четвёртый релиз с догадкой.
5. **Пути установки перечисляются, а не угадываются.** ProgramData не попал в
   `is_installed_location()` — релей годами читал не тот `upstream.txt`.
6. **Службу нельзя обновить, пока её задача запускает тот же exe.** Перед
   `copy_over` — `disable_watchdog()`.
7. **Никаких «исправлено» без воспроизведения.** Каждый фикс сопровождался
   падающим тестом; итоговое «работает» пришло только из полевого отчёта.

## Опровергнутая гипотеза (не повторять)

`os error 10013` на `127.0.0.1:53129` объясняли сокетом, который «только bound,
не listen». Замер показал: такой сокет не появляется в extended TCP table и не
мешает bind'у. Правка в `portcheck` была откачена. Настоящая причина 10013
остаётся открытым пунктом роадмапа.

## v1.6.0: закрытые хвосты

- **Дверь переживает релей.** Watchdog — отдельная задача, она держит
  `127.65.71.1/2:443` и публикует свежую метку в `door.json`. Релей читает метку
  и уступает bind вместо ложной карточки «порт занят». Принятые соединения
  повторяют туннель до 30 с — TLS ClientHello клиента ждёт, а не получает RST.
  Окно `ANSWER_TTL` перестало быть ошибкой.
- **Тёплый проход называет шаг.** `WARM_STEP` + имя в логе перед завершением
  процесса. Причина залипания всё ещё неизвестна, но больше не придётся гадать.
- **`--relay-status`** — одна read-only команда вместо четырёх логов.
- **`WSAEACCES`** — отчёт называет проверки (holder, exclusion range, http.sys
  URLACL) и оставшихся подозреваемых; «антивирус» больше не голословный.
- **In-process путь.** При реальном изменении `OAG_GATEWAY` перезапускается
  только `language_server`, редактор не трогается. Дверь остаётся фолбэком.

## Что осталось

- точный источник `WSAEACCES` 10013 (WFP / эксклюзивная привязка) не измерен —
  но теперь отчёт сужает поиск;
- причина залипания `warm_forever` не установлена — но она будет названа в логе;
- нагрузочный тест «20 перезапусков релея при живом DNS-кэше» не проводился —
  дверь в watchdog и 30-секундное ожидание туннеля ещё не прошли его.

# watchdog и отравленная запись
